# 项目方申请、HAFleet 批准、Agent 完成任务：人工验证

日期：2026-09-06。状态：已完成环境预检查，等待操作员开始本轮申请。

本指南验证当前可运行路径：项目房间直接发起角色申请。当前测试环境使用注册令牌；
它不验收尚未实现的 Palpo 自助 App Service 入驻与独立接洽大厅。
对应未来需求见 [Palpo 接入需求草案](../../knowledge/requirements/req-palpo-hafleet-onboarding.md)。

## 本轮约定

- 操作员在 Robrix2 扮演项目方，再在 HAFleet Web 扮演资源提供方。
- 助手逐步解释并检查结果；不提前替操作员提交申请或批准。
- 使用当前桌面 Robrix2 与既有测试项目房间，保留历史测试记录。
- 创建一条新的 `coding` 申请，10,000 token、每日申请 2,000。
- 预检查预计由新的 Codex `gpt-5.6-sol`、high 配置提供服务；批准前须重新核对实时预览。
- 已手动停止的旧 Agent 不恢复；手工 onboarding 的 Agent 不能因全局健康而绕过项目方准入。
- 当前总额度为 250,000，已有承诺 150,000，可分配 100,000；这些是预检查值，不是使用量。

## 步骤 1：项目方查看能力

在已打开的 Robrix2 项目房间主时间线发送：

```text
!offer
```

预期：接洽代表回复包含 `coding` 的能力清单、预计服务配置，以及当前房间不在白名单的说明。
此步不创建申请、不消耗新的接洽额度。没有回复时先检查代表成员关系及事件通道，不重复发请求。

## 步骤 2：项目方发起申请

确认能力后，在同一主时间线发送一次：

```text
!request coding 10000 2000
```

预期：代表回复申请已收到、等待 HAFleet 决定。新的 Matrix 消息会产生新请求，
所以不要把多次发送当成同一请求的无害重试。记录这次消息及对应申请 ID，避免误看历史申请。

此命令申请的是角色，不是直接指定某个 Agent 名称。

## 步骤 3：HAFleet 查看并批准

打开本地控制台的“接洽”页面：`http://127.0.0.1:13200/engagements`。

1. 刷新，找到本轮新出现的待审批 `coding` 申请。
2. 核对项目、申请人、10,000 token，以及“将由谁服务”的实际模型和新建计划。
3. 点击“批准”，填写分配额度 10,000。
4. 展开“设置项目所有者和私密审批房间”。本轮使用既有项目所有者与私密加密审批房间；
   完整 MXID 和真实房间 ID 由受限运行配置或 Robrix 房间详情核对，不能用显示名称代替。
5. 点击“确认批准”一次，等待结果。

预期：后端记录批准并准备 Agent。即使已有同项目绑定，也应确认本次新建 Agent 的所有者绑定；
不能把字段留空必然成功当作前提。实际错误必须保留并解释，不以反复批准掩盖失败。

## 步骤 4：确认申请已履约

同时核对：

- 接洽记录进入“进行中”，显示实际服务 Agent 和获批额度。
- 履约阶段完成，身份、所有者绑定、目标项目入房均成功。
- Robrix2 项目成员列表能找到同一个 Agent 的完整 Matrix 身份。
- 新建的按任务运行 Agent 可以空闲，不能仅凭没有常驻 tmux 进程判断失败。

“已批准”或“进行中”本身不是任务成功证据。创建、绑定或入房失败时停留在本步处理。

## 步骤 5：项目方使用 Agent

在 Robrix2 使用原生成员选择器提及本次实际服务的 Agent，再发送下面的任务正文。
不要只粘贴显示名称，不要误选旧的已停止 Agent 或“通知整个房间”。

```text
/task 请在你的工作目录内新建 projects/ux-request-demo。
使用 Node.js 实现 sum(numbers)：空数组返回 0，支持正数和负数，非数组或包含非有限数字时抛出 TypeError。
使用 Node.js 内置 node:test 编写并运行测试，覆盖空数组、正负数、非数组、字符串元素和 NaN。
仅修改这个新项目目录，不提交、不推送、不部署。
完成后在本线程回复修改了什么、运行的测试命令和实际测试结果。
```

预期：出现属于本次任务的确认与执行记录，结果留在正确项目线程。
如出现运行时权限请求，到既有私密审批房间核对请求内容，再通过原生批准控件处理。
普通聊天“同意”不是有效权限决定；提供方批准 token 额度也不等于批准所有本地操作。

## 步骤 6：核实完成结果

- 核对该任务确实完成，Agent 回复与本次线程一致。
- 从该 Agent 实际工作目录检查产物并运行其报告的测试命令。
- 至少验证空数组、正负数、非法元素、NaN 以及非数组行为。
- 把“Agent 说测试通过”和“独立执行测试通过”分别记录。
- 若任务失败或结果未知，保留原始状态，不标记整条流程通过。
